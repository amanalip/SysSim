1. **Audit scope and evidence.** This report originally recorded 11 findings against commit `2134c1c`. All 11 have now been implemented on September 5, 2026, in one commit per finding. The original evidence below is retained as historical context; each finding ends with its implementation status. The filename follows the requested September 4, 2026 label. Inspection used the local Vite application in Chromium at 1440×900 and 390×844, with light and dark themes, plus source review. Browser checks covered the header, selected-node controls, canvas toolbar, playback bar, properties overlay, and opening/closing Snapshots, Chaos Drills, Keyboard Shortcuts, and Command Palette. This is a focused UI audit, not an exhaustive review of every scenario, property editor, simulation result, browser, or export workflow. “High” means controls become inaccessible or invisible; “Medium” means misleading behavior or readability problems; “Low” means clarity or persistence improvements. The corresponding implementation commits accompany this updated report.

2. **Implemented — High — Edge-routing buttons disappear off the screen on mobile.** Browser-confirmed in both themes. At 390×844, close the properties panel and inspect the top canvas toolbar: Bezier, Orthogonal, and Straight are outside the left edge. The Bezier button measured `x = -258.5px`, width `67.03px`. The toolbar is a single non-wrapping row anchored to the right, and its canvas parent clips overflow. These are fixed interface controls, so panning the diagram does not recover them. See [CanvasHud.module.css](src/components/canvas/CanvasHud.module.css) (`.hudContainer`, `.routingGroup`) and [ArchitectureCanvas.module.css](src/components/canvas/ArchitectureCanvas.module.css) (`.canvasContainer`). Suggested fix: wrap the toolbar or put routing choices in a compact, labeled menu at narrow widths. Acceptance check: all routing and zoom controls remain reachable at 360px and 390px widths in both themes. **Implementation (September 5):** The toolbar now wraps within the canvas width and has larger mobile controls. Browser checks passed at 360px, 390px, and 1440px in both themes.

3. **Implemented — High — Keyboard focus can land on invisible node actions.** Browser-confirmed, with the same CSS applying to both themes. Move the pointer away from a node and focus its footer action, such as “Inject failure for App Server.” The browser reported `document.activeElement === button` while the parent action group still had computed `opacity: 0`. Keyboard navigation can therefore reach an invisible fault-injection or delete control. See [CustomComponentNode.module.css](src/components/canvas/nodes/CustomComponentNode.module.css) (`.quickActions` and `.nodeContainer:hover .quickActions`). Suggested fix: also reveal actions on `:focus-within`, and provide a usable presentation for touch input. Acceptance check: Tab through an unhovered node's actions and verify the icon and focus indicator remain visible throughout. **Implementation (September 5):** Node footer actions now appear on focus-within and stay visible for coarse-pointer or non-hover input. Browser keyboard-focus verification passed.

4. **Implemented — Medium — “Import trace” is squeezed into an icon-sized button.** Browser-confirmed on desktop and mobile in both themes. The playback bar renders the words “Import trace” using `.controlBtn`, which has a fixed 30×30px size. The label wraps and spills beyond its intended button area. A mobile rule attempts to enlarge `.controlBtn`, but the later base rule overrides its width; the minimum-height rule does not solve the text width. See [SimulationControls.tsx](src/components/playback/SimulationControls.tsx) (the workload trace import button) and [SimulationControls.module.css](src/components/playback/SimulationControls.module.css) (`.controlBtn` and the 640px media query). Suggested fix: give text actions an auto-width class with suitable padding; inspect the seed “Copy” action using the same class. Acceptance check: labels fit inside their clickable borders at desktop and mobile sizes without colliding with neighboring controls. **Implementation (September 5):** Import trace and Copy now use auto-width text buttons. Mobile icon sizing is corrected, and the playback bar wraps within the canvas to accommodate the wider labels.

5. **Implemented — Medium — Disabled canvas Undo/Redo look enabled.** Browser-confirmed in dark mode; source styles are shared across themes. With an undoable edit and no redo history, Undo was enabled and Redo was disabled, yet both computed to the same foreground color, `opacity: 1`, and `cursor: pointer`. The canvas toolbar has hover styles but no disabled-state treatment. A user can reasonably think Redo is broken when clicking it does nothing. See [CanvasHud.module.css](src/components/canvas/CanvasHud.module.css) (`.iconBtn`) and [CanvasHud.tsx](src/components/canvas/CanvasHud.tsx) (Undo/Redo buttons). Suggested fix: add visible disabled styling, suppress enabled hover feedback for disabled buttons, and explain unavailable history where useful. Acceptance check: compare empty history, available Undo, and available Redo in both themes. **Implementation (September 5):** Disabled Undo/Redo now have reduced opacity, an unavailable cursor, no enabled hover treatment, and explanatory tooltips.

6. **Implemented — Medium — Reduced motion still allows animated canvas zoom and fit.** Browser-confirmed for Zoom in; related Fit behavior is source-confirmed. Enable Reduce motion and click Zoom in. While the root had `data-motion="reduced"`, animation-frame sampling captured multiple intermediate viewport transforms, including scales `1.22137`, `1.24446`, `1.35844`, and `1.46565`. The toolbar explicitly passes 200ms durations for zoom and 300ms for fit; another canvas fit path uses 400ms. CSS motion suppression does not stop these JavaScript viewport animations. See [CanvasHud.tsx](src/components/canvas/CanvasHud.tsx) and [ArchitectureCanvas.tsx](src/components/canvas/ArchitectureCanvas.tsx). Suggested fix: use the effective application/system motion preference to choose zero-duration viewport changes. Acceptance check: verify zoom in, zoom out, toolbar fit, and automatic fit under both explicit and operating-system reduced motion. **Implementation (September 5):** A shared reactive motion hook now controls particles and toolbar/auto-layout viewport durations. Browser frame sampling confirmed immediate explicit and system-reduced zoom; explicit zoom-out and fit also passed.

7. **Implemented — Medium — Muted text is too faint in light mode.** Browser-computed colors and source values confirm a readability weakness. For example, an unselected playback speed label uses `#8c959f` over `#ffffff`, a calculated contrast ratio of approximately `3.04:1`; the same muted token over `#f6f8fa` is approximately `2.85:1`. This token is used for small secondary labels throughout the interface. See [theme.ts](src/theme.ts) (`light.textMuted`) and [SimulationControls.module.css](src/components/playback/SimulationControls.module.css) (`.speedPill`). Suggested fix: darken the light-theme muted token or introduce separate tokens for readable secondary text and decorative details. Acceptance check: inspect actual small-text/background combinations in the palette, node metadata, playback controls, and dialogs, rather than checking only primary text tokens. **Implementation (September 5):** The light muted-text token is now #626c77 in CSS and theme metadata. Contrast regression checks cover primary, secondary, and tertiary light backgrounds.

8. **Implemented — Medium — The selected speed label has weak contrast in dark mode.** Browser-confirmed: the selected `1x` button computes to white text on `#58a6ff`, approximately `2.53:1` contrast, at a 10px font size. See [SimulationControls.module.css](src/components/playback/SimulationControls.module.css) (`.speedPillActive`) and [theme.ts](src/theme.ts) (`dark.accentPrimary`). Suggested fix: choose a contrasting foreground for the bright dark-theme accent, or use a darker selected background. Acceptance check: inspect every selected speed in both themes and check other white-on-accent text buttons for the same pattern. **Implementation (September 5):** A theme-specific text-on-accent token now supplies readable text on speed pills and other accent-filled controls. The play action uses a solid accent surface. Both theme contrast checks passed.

9. **Implemented — Medium — The narrow-screen action panel declares menu semantics without menu behavior.** Browser DOM and source-confirmed. At mobile width, open Architecture actions. The container has `role="menu"`, but its children remain ordinary buttons with no menu-item roles, and the header implements no arrow-key navigation or initial item focus. See [Header.tsx](src/components/layout/Header.tsx) (`architecture-actions` and the open/close effect). Suggested fix: either present this as a labeled disclosure containing ordinary buttons, or implement the complete menu interaction pattern. Acceptance check: verify opening, keyboard navigation, Escape, and focus return with the chosen semantics. This finding concerns the semantic/interaction mismatch; assistive-technology testing was not performed in this audit. **Implementation (September 5):** Architecture actions now use a labeled disclosure group with ordinary Tab navigation; Escape returns focus to the trigger. Browser verification passed.

10. **Implemented — Low — Three mobile action rows have no visible text labels.** Browser-confirmed. Open Architecture actions at 390×844: the last three full-width rows show only keyboard, accessibility, and moon/sun icons. Their tooltips or accessible names help some users, but their purpose remains unclear to a sighted touch user, especially the accessibility icon. See [Header.tsx](src/components/layout/Header.tsx) and [Header.module.css](src/components/layout/Header.module.css) (narrow-screen `.actionsSection .iconBtn`). Suggested fix: show “Keyboard shortcuts,” “Reduce motion,” and a theme action label in the expanded panel, including motion state where appropriate. Acceptance check: identify each action and its state without hovering or relying on an icon's meaning. **Implementation (September 5):** The expanded action panel now shows Keyboard shortcuts, Reduce motion with On/System state, and the next theme action as visible labels.

11. **Implemented — Low — Explicit reduced-motion preference resets after reload.** Browser-confirmed. Enable Reduce motion, reload, and inspect the button: `aria-pressed` returns to `false`. The store initializes the preference to `system` and does not persist it, unlike theme and keyboard-shortcut preferences. See [use-store.ts](src/store/use-store.ts) (`motionPreference`, `setMotionPreference`, and adjacent preference setters). Suggested fix: persist and safely restore the explicit preference, with a system-mode fallback for absent or invalid stored values. Acceptance check: verify both preference values survive reload, and storage failures do not break application startup. This is a persistence improvement; the existing system preference is still respected. **Implementation (September 5):** Both motion modes are saved and safely restored. Tests cover missing/invalid storage and read/write failures, and browser reload verification passed.

12. **Implemented — Low — “Connection tutorial” is only a four-second notification.** Source-confirmed usability issue; the timeout was not separately timed in the browser audit. The control's accessible name promises a tutorial, but its handler displays a long instruction string in a toast. All toasts are removed after 4000ms, with no pause-on-hover/focus behavior in the toast component. This gives a new user little time to read the instructions and try connecting nodes. See [CanvasHud.tsx](src/components/canvas/CanvasHud.tsx) (Connections button), [use-store.ts](src/store/use-store.ts) (`addToast`), and [Toast.tsx](src/components/ui/Toast.tsx). Suggested fix: use dismissible persistent help with a simple connection example, or label the action as a quick tip and keep it available long enough to use. Acceptance check: users can read and refer to the guidance while performing the connection action. **Implementation (September 5):** Connection help now opens persistent, nonmodal instructions with a Client-to-App-Server example, an explicit close button, and scoped Escape handling. Browser and automated checks confirmed persistence and focus return.

13. **Previously reported issues already fixed; do not count these as open findings.** Commit `d0e8d81` connected the reduced-motion toggle to request particles and added a visible pressed state. Commit `2134c1c` fixed the invisible healthy-state power icon using `currentColor`. The power action marks a component down and restores it on the next click. The viewport-animation and preference-persistence findings above are additional issues beyond those fixes.
